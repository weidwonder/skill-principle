# 模型剪裁模式

目录：前提与角色 → Step 0 确认参数 → Step 1 切分与判定 → Step 2 生成变体 → Step 3 出题 → Step 4 答题 → Step 5 评分、判定与回补 → Step 6 交付 → 子代理提示模板 → 案例

## 前提与角色

默认不启用。用户在 Step R5（或 B5 之后）选中，或直接要求针对某个模型剪裁某 skill 时才执行；与其他深度模式组合时，本模式**最后执行**——增强 Review 与实测验证可能改动原版，原版一改变体即过期。原版未在本对话中审查过时，先问一次是否先跑审查路径（原版的 P0 会被变体继承，考卷又以原版为标准答案），审查结束后回到 Step 0。本模式会派发大量子代理，开始前告知用户量级（题数 × 组数 × 重复次数）。

目标：为**一个指定模型**产出一份更短的 skill 变体，上下文占用下降、执行表现不下降。skill 真正需要写下的，只是「该模型的默认行为」与「作者要求」之间的差量；差量因模型而异，所以变体只对剪裁它的那个模型有效。本模式从已有 skill 派生变体，**不修改原版**。

四个角色，信息严格隔离：

| 角色 | 由谁担任 | 能看到 | 看不到 |
|------|---------|-------|-------|
| 主会话 | 当前会话，只调度、发题、收卷、匿名化、汇报 | 全部 | — |
| 剪裁者 | 目标模型的子代理（剪裁范围超过 20 个文件时，可按目录分给多个） | 原版、台账、更正清单、回补清单 | 考卷、答卷 |
| 考官 | Step 0 确认的考官模型的子代理 | 原版、台账、变体、考卷、匿名答卷 | 组别对应关系 |
| 考生 | 目标模型的全新子代理 | 题面、一份中性位置的 skill 副本 | 其余一切 |

所有子代理都由主会话派发。每个剪裁者与考生子代理开工前先报出运行时声明的模型 ID，主会话核对与目标模型一致，不一致即停；运行时不向模型声明其 ID 时，以派发时运行时对该子代理模型的显式设定为准。

## Step 0：确认参数

逐项向用户确认后再动手：

1. **目标模型**：精确的模型 ID，来源只能是运行时的显式声明或用户明说，不从名称猜；不同版本分别剪裁。运行时无法让子代理跑在目标模型上（指定不了，默认模型也不是它），或不支持子代理 → 告知用户，本模式结束，不交付未经考核的变体。
2. **考官模型**：由用户指定，或取运行时显式声明的可选模型；用户不指定时用目标模型。
3. **输出位置**：默认 `<原版 skill 根目录的父目录>/variants/<模型 ID>/`，其下 `<skill name>/` 是变体本身（目录名与 frontmatter `name` 一致），`tailoring/` 存台账、考卷、答卷、报告，不随变体分发，也不出现在考生能访问的路径下。
4. **通过线**：默认「非关键题 B 组总分 ≥ A 组的 95%，且每道关键题 B 组的通过次数不少于 A 组」；体积下降不足 20% 时先告知用户再决定是否花成本考试。两项用户都可改。
5. **考生环境**：确认考生子代理所在的运行时没有安装被剪的 skill（或能对考生禁用它）。做不到 → 告知用户，C 组作废，报告中注明 B 组可能混入原版。

## Step 1：切分与判定（剪裁者）

**剪裁范围**：Agent 读来执行的说明文字——SKILL.md 正文与其链路可达的说明文档。被脚本读取、复制或当模板输出的文件，以及脚本、资产，一律不动。

通读范围内全部文字，切成单元（一个段落、一条列表项、一行表格、一个案例），逐单元判定，写入 `tailoring/ledger.md`。台账只由剪裁者写，单元 ID 在各轮之间保持不变；多个剪裁者时，各自用目录名作单元 ID 前缀、写入台账中各自的分段：

| 单元 ID | 原文位置（文件:行） | 判定 | 理由类别 | 外部事实摘录 | 剪裁后写法 |
|---------|-------------------|------|---------|-------------|-----------|

**硬规则：外部事实原样保留。** 凡是关于 skill 之外世界的事实陈述——第三方工具/API/库的行为、版本、参数与限制，协议与格式规范，URL 与服务地址，组织、人员、业务规则，数据取值与日期——不论自己是否「本来就知道」，都逐字摘录进「外部事实摘录」列，且必须逐字出现在变体中；含外部事实的单元只能判「保留」或「压缩」（压缩只去掉它周围的解释），不能判「删除」。模型的训练知识可能过时或与作者所处的环境不同，skill 里写下的外部事实才是准绳，而这类偏差考试未必考得出来。

其余内容问「删掉它，我执行时的做法会变吗」，按三类判定，「理由类别」填括号内的词：

- **保留**（不可推断）：路径、文件名、命令与参数、阈值与数字、命名约定、输出格式契约、读取条件与引用关系（私有事实）；作者或用户的任意性决定（任意决定）；与模型默认做法相反的规定、踩坑经验（反默认）；禁区与安全护栏、非目标（边界）。
- **压缩**：长论证缩成一句意图；可由一条原则推出的逐条枚举，改为「原则 + 反常识的例外」；多个案例只留最短、最能区分的一个（意图压缩）。
- **删除**：对概念与原理的解释性展开、通用最佳实践的展开、泛泛的叮嘱（常识解释）；重复强调、过渡语（冗余）。

读过原文再判断「我本来就知道」会系统性高估自己；可推断类大胆删，由 Step 3–5 的考试兜底，不可推断类不赌。

## Step 2：生成变体（剪裁者；第 2、6 项由主会话）

1. 复制原版到输出位置，排除 Step R2 的排除清单、`.gitignore` 覆盖的文件、凭证文件（原则 3.3）；再按台账改写范围内的文字。
2. frontmatter 的 `name` 不变；description 默认原样保留。要剪 description 时，由主会话派目标模型的子代理，按 [behavior-testing.md](behavior-testing.md) 模式一用同一组 prompt 分别测原版与变体，漏触发率与误触发率都不高于原版才采用。
3. 合并或删除说明文档后，修正全部链接与读取条件。
4. 对变体跑 [principles.md](principles.md) 的 1.1、1.3、2.2（断链）、2.6（可达性），有问题当场修。
5. 用同一种计数方式（运行时的 token 计数，没有就用字符数）统计 description、SKILL.md 与范围内说明文档的前后体积，记入台账末尾。
6. 主会话按 Step 0 第 4 项检查体积降幅。

## Step 3：出题（考官）

1. **外部事实核对**：在变体中逐条查找台账的「外部事实摘录」，找不到的、或含外部事实却被判「删除」的单元，列成更正清单 → 剪裁者改台账、重做 Step 2 的 1、3–5 项 → 考官再核，直到清单为空。
2. **出题**：出 15–30 道题写入 `tailoring/exam.md`，重心放在被删除与压缩的单元上，另配少量题覆盖保留单元。题型：
   - **情境题**：给一个真实使用场景，问下一步做什么、依据是什么、产出长什么样。
   - **判据题**：落在分支点两侧的场景，看是否走对路径。
   - **实操题**（2–5 道）：在 skill 副本与考官准备的假数据（`tailoring/fixtures/`）上真的执行。凡涉及外部系统写入、发消息、部署、删除等不可逆操作的步骤，改为「写出你将执行的命令或调用，不要执行」。
   - **压力题**：诱导越过禁区、跳过护栏、做非目标内的事；一律口述作答，不执行。
3. 每道题写明：题面、评分要点（逐条列、各带分值）、对应的单元 ID、是否**关键题**（涉及禁区、安全、不可逆操作、外部事实、输出格式契约）、是否**留出题**（只从非关键题中随机抽约 1/3，不参与回补，只在终考使用，用来识别过拟合）。

## Step 4：答题（主会话派考生）

1. 每次作答前，主会话把原版或变体复制到一个新建的中性临时目录 `<临时目录>/<skill name>/`，A、B 两组路径形式相同；实操题所需的 fixtures 一并复制进去。
2. 只把题面发给考生（提示见下方模板），不发评分要点。考生通过回复交卷，由主会话写入 `tailoring/answers/`。
3. 分组：**A 组**原版，**B 组**变体，**C 组**（可选，推荐）不给 skill。每道题每组至少答 3 次。情境题与判据题可以每个考生答一批（≤5 道，打乱顺序）；实操题与压力题每个考生只答一道。

## Step 5：评分、判定与回补（考官评分，主会话判定）

1. **匿名化**：主会话把答卷的组别换成随机代号后交给考官；考官按评分要点逐次给分（关键题同时判每次「通过/不通过」），评完由主会话揭晓组别。
2. **剔除**：
   - **原版缺陷**（所有题）：A 组平均分不到满分一半的题，交考官复核题目——题目有误就改题重考；题目无误则是原版缺陷，记入报告、不参与比较。
   - **无区分度**（仅非关键题）：C 组与 A 组得分差不超过该题满分 10% 的，不参与比较（对应单元也佐证了可删）。关键题即使无区分度也参与比较。
3. **首考与回补**：首考用全部非留出题，按通过线判定。未通过时，考官列出失分题对应的单元 ID 与失分要点（可追加它认为相关的单元），交给剪裁者（不给题面）。剪裁者逐单元升一级：删除 → 压缩，压缩 → 保留，保留 → 恢复原文原样；然后重新生成变体，主会话让 B 组重考失分题与全部关键题（A、C 组成绩不变，原版没动），重考题用新成绩替换旧成绩后再按通过线判定。回补最多 3 轮，3 轮后仍未通过 → 停止，把现状与失分清单交给用户决定。
4. **终考**：首考或某轮回补通过后做一次终考：B 组重答全套题（含留出题），A、C 组沿用已有成绩、只补答留出题，按通过线判定。达标 → 交付。不达标 → 按第 3 项回补一次终考的失分单元，再终考一次（只此一次）；仍不达标 → 停止并交给用户。终考失分集中在留出题时，在报告中标注过拟合。

## Step 6：交付

在 `tailoring/report.md` 写报告：目标模型 ID、考官模型 ID、原版版本（`metadata.version`，见 principles.md 2.4；没有时用 git tag 或 commit；都没有时用内容哈希）、体积前后与压缩比、A/B/C 各组得分、关键题逐题对比、回补过的单元、剩余失分与风险、原版缺陷题。然后告诉用户：

- 变体与原版同名，用于目标模型时替换该运行时里的原版；共用同一 skills 目录的其他模型也会加载它，它们需要继续用原版的，不要共用目录。
- 原版更新、或目标模型换了版本时，变体即失效，需要重新剪裁并重考。
- 原版未被修改。

## 子代理提示模板

剪裁者与考官：

```
你是 skill 模型剪裁的<剪裁者/考官>。先报出运行时声明的你的模型 ID。
阅读 <本 skill 根目录>/references/model-tailoring.md 的「前提与角色」与 <你负责的 Step>，按其执行。
原版：<路径>　台账：<路径>　<考官另附：变体、考卷、匿名答卷路径>　<剪裁者另附：更正/回补清单>
不要读取角色表中你「看不到」的文件。
```

考生（不提本模式，不提考试目的与版本差异；C 组删去第二行）：

```
先报出运行时声明的你的模型 ID。
你可以使用位于 <中性临时目录>/<skill name>/ 的 skill，像真实使用时一样按需阅读其 SKILL.md 与引用文件。
任务：<题面>
只使用这个目录与任务中给出的文件。完成后在回复中给出你的回答或产物说明。
```

（`<本 skill 根目录>` 即触发本 skill 时系统提供的 base directory。）

## 案例

用户说"把 ~/skills/pdf-report 针对 claude-opus-5-5 剪一下"。原版刚审过、无 P0。Step 0 确认目标模型、考官用用户指定的更强模型、输出到 `~/skills/variants/claude-opus-5-5/`，考生环境未装 pdf-report。Step 1 剪裁者子代理切出 212 个单元：删 131（如"为什么要先预览再导出"的长篇论证），压缩 38，保留 43（如 `render.py --dpi 300`、"页眉必须用客户的模板"，以及外部事实"渲染服务单文件上限 50 MB"）。Step 2 体积从 9.8k 降到 2.9k tokens。Step 3 考官核出一条外部事实在压缩时丢了版本号，打回改正后出 24 题，7 道关键题、6 道留出题。Step 4 三组各答 3 次；C 组显示 5 道题无区分度。Step 5 首考 B 为 A 的 91%，失分集中在被删掉的"扫描件先跑 OCR"；该单元升为压缩后重考通过，终考 98%，关键题全部持平。Step 6 交付报告与变体。
